a) Muestre que el algoritmo QUICKSORT_RC(A, 1, n) ordena correctamente el arreglo A[1..n]. 

	El algoritmo QUICKSORT_RC es una versión modificada del QuickSort estándar que utiliza un 
	bucle while para eliminar la segunda llamada recursiva, una técnica conocida como recursión 
	de cola. 
	Demostración de Correctitud: 
	El algoritmo funciona bajo el mismo principio de "divide y vencerás" que el QuickSort 
	estándar: 
	1. Dividir: El procedimiento PARTITION(A, p, r) divide el arreglo A[p..r] en dos sub-arreglos 
	(posiblemente vacíos) A[p..q-1] y A[q+1..r] tal que cada elemento de A[p..q-1] es menor o 
	igual a A[q], y A[q] es menor o igual a cada elemento de A[q+1..r]. 
	2. Vencer: En lugar de hacer dos llamadas recursivas, el algoritmo hace lo siguiente: 
	○ Llama recursivamente a QUICKSORT_RC para ordenar el sub-arreglo izquierdo 
	A[p..q-1]. 
	○ Itera para ordenar el sub-arreglo derecho. Lo logra actualizando el puntero p a q+1. 
	El bucle while se encarga de que el nuevo sub-arreglo A[q+1..r] sea procesado en la 
	siguiente iteración. 
	El algoritmo es correcto porque cada paso asegura que una porción del arreglo queda 
	ordenada. El bucle while y la llamada recursiva garantizan que todos los sub-arreglos 
	generados por PARTITION serán procesados hasta que todo el arreglo esté ordenado. El caso 
	base se da cuando p >= r, momento en el que el sub-arreglo tiene 0 o 1 elemento y ya se 
	considera ordenado.

b)  Describa un escenario en el cual la profundidad de la pila de QUICKSORT_RC es Θ(n) para un arreglo de n elementos.
	La profundidad de la pila está determinada por la cadena de llamadas recursivas anidadas. 
	En QUICKSORT_RC, la única llamada recursiva es para el sub-arreglo izquierdo: 
	QUICKSORT_RC(A, p, q-1). Por lo tanto, para maximizar la profundidad de la pila, necesitamos 
	un escenario donde esta llamada recursiva se haga repetidamente sobre un sub-arreglo casi 
	tan grande como el anterior. 
	Un escenario de peor caso que lleva la profundidad de la pila a Θ(n) ocurre cuando la 
	partición es consistentemente desbalanceada, generando un sub-arreglo izquierdo de 
	tamaño n-1 y uno derecho de tamaño 0 en cada paso. 
	Escenario: 
	● Entrada: Un arreglo que ya está ordenado ascendentemente (por ejemplo, [1, 2, 3, 4, 
	5]). 
	● Algoritmo de Partición: Uno que consistentemente elige el último elemento como 
	pivote. 
	Explicación detallada: 
		1. Llamada 1: QS_RC(A, 1, 5). El pivote es A[5]=5, el elemento más grande. PARTITION no 
		mueve nada, y q termina siendo 5. El algoritmo llama recursivamente a QS_RC(A, 1, 4). 
		Profundidad de pila: 1. 
		2. Llamada 2: QS_RC(A, 1, 4). El pivote es A[4]=4, el más grande del sub-arreglo. q termina 
		siendo 4. Se llama recursivamente a QS_RC(A, 1, 3). Profundidad de pila: 2. 
		3. Llamada 3: QS_RC(A, 1, 3). El pivote es A[3]=3. q es 3. Se llama a QS_RC(A, 1, 2). 
		Profundidad de pila: 3. 
		Este patrón predecible continúa. Cada llamada recursiva añade un nuevo marco a la pila para 
		un subproblema de tamaño solo uno menor que el anterior (k-1), llevando directamente a una 
		cadena de n-1 llamadas recursivas anidadas, lo que resulta en una profundidad de pila de 
		orden Θ(n). 

c)Modifique el código de QUICKSORT_RC tal que en el peor caso la profundidad de la pila sea Θ(log n)
	QUICKSORT_RC_MOD(A, p, r)
    while p < r do
        // Particionar y encontrar el punto medio q
        q = PARTITION(A, p, r)

        // Si el sub-arreglo izquierdo es más pequeño que el derecho
        if (q - p) < (r - q) then
            // Recurrir sobre el lado izquierdo (más pequeño)
            QUICKSORT_RC_MOD(A, p, q - 1)
            // Iterar sobre el lado derecho (más grande)
            p = q + 1
        else
            // Recurrir sobre el lado derecho (más pequeño)
            QUICKSORT_RC_MOD(A, q + 1, r)
            // Iterar sobre el lado izquierdo (más grande)
            r = q - 1
	
	Para reducir la profundidad de la pila en el peor caso a O(log n), se modifica QUICKSORT_RC para que siempre ordene
	primero la sublista más pequeña mediante recursión, y procese la más grande con iteración. Esto evita acumulación 
	excesiva de llamadas recursivas.
